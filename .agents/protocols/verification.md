# 最小工程变更与验证协议

## 编码前

- 优先确认目标、已有行为、相关文件、受影响依赖、复现手段和测试路径。
- 方案有多种时选**满足成功标准的最简单方案**。若关键假设影响安全或接口，先核查或说明保守假设。
- 查看现有工作区差异，辨别其他 Agent 与用户的变更。禁止覆盖无关工作。

## 修改中

- 只修改能追溯到当前需求的文件和代码；沿用已有风格、模式与依赖。
- 不为一次性任务引入抽象、全局配置或通用框架。
- 不随手美化、重排、重构邻近代码；不删除已有无关死代码。
- 删除**本次改动**产生的孤儿导入、变量、函数、无用测试和废弃引用。
- 防护与错误处理要覆盖实际风险，不要以「简单」为由省略认证、授权、敏感数据保护等必要措施。

## 验证层级

1. **静态**：检查目标 diff，语法、类型与配置是否有效（按适用性）。
2. **定向**：针对改动的函数、模块或 Bug 复现场景测试。
3. **回归/集成**：跨模块或高风险修改时扩大范围。
4. **交付核查**：逐项核对目标、范围、假设、产物、测试与残余风险。

不可执行某项检查时陈述实际限制；不要假造命令、测试运行或测试结果。

## 规则/文档变更

- 回读改动段，检查旧术语、失效引用与相对链接；无适用自动化测试时如实说明；
- 检查文档声明的结构、路径与版本是否仍然成立；
- 用一个 L0 和一个 L2 场景走查，确认没有强制过度拆解或跳过验证；
- 治理规则修改记录「现状 → 建议 → 收益 → 副作用」，并在交付说明或提交信息中保留。

## 行动审批与 Git

- 运行时权限与用户授权高于任何仓库文档。
- 审批不可用不等于已授权；L3 门禁见 `AGENTS.md` §3（无独立复核且无用户知情批准时必须 BLOCKED）。
- 破坏性操作前记录精确目标、授权来源与回滚/备份；能 dry-run 就先 dry-run，执行后回读结果。
- 未经授权不执行破坏性回滚、删除数据、外部发布、`git push`、批量覆盖或超范围提交。
- 不要求每个原子节点自动提交；若允许提交，只暂存本次工作所需内容并审阅 diff。
- 若用户已有未提交工作，必要时使用隔离工作树或只读/补丁交接；不能保证隔离时应主动避免并发写入。

## 完成定义（DoD）

所有适用条件均满足，才可宣布完成：

- 用户目标及显式边界已经满足；
- 改动范围可解释且最小，没有擅自追加功能；
- 已执行适用的验证并诚实报告结果；
- 独立节点成果已收敛，接口和冲突已经处理；
- 限制、未确认假设及剩余风险如实披露。

若只完成部分事项，应明确标记为部分完成。
