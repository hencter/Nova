# 运行时能力发现与降级

## 目的

选择编排方式**之前**，先确认当前 Agent 实际拥有什么能力。不要把某个产品的功能当成通用标准。

## 最小能力检查

只探测与当前任务相关的项；能从工具清单或已执行操作确认的，不重复探测。

| 能力 | 证据 | 不可用时 |
| --- | --- | --- |
| 文件读取 | 读取工具可用或已成功读取 | 请求用户提供内容，或基于已有材料完成 |
| 文件写入 | 已授权且存在写入接口 | 提供补丁/完整文本，不声称已落盘 |
| 命令/测试执行 | 有可用的执行环境 | 静态检查 + 可复现指令 + 未验证说明 |
| Skill 发现 | 能列出或读取指定 Skill | 按明示路径读取；读不到就说明限制 |
| 子代理 | 有明确的分派接口 | 主 Agent 按同一契约串行完成 |
| 并行执行 | 有调度接口且资源可隔离 | 按依赖顺序串行 |
| 独立审查 | 有独立代理或独立上下文 | 自检，并如实说明不具备独立性 |
| 网络/外部服务 | 有实际访问权限 | 离线完成，标注未核查的外部事实 |
| 持久化/跨会话记忆 | 有可写且约定的位置 | 只在交付摘要中记录，不承诺跨会话记忆 |

## 决策规则

1. 按问题选能力，不按品牌选能力。
2. 没有子代理接口，就不用「代理配置文件」冒充已执行委派。
3. 有并行能力但会改同一文件/状态时，仍需串行或指定唯一作者。
4. 工具失败先分析原因；只有能减少不确定性时才换备用工具。
5. 模型、工具与角色权限写在调用时的任务契约里，不写进固定的通用命令。
6. 运行时的真实权限与审批永远高于本仓库的任何文字。

## 协作模式

| 模式 | 适用 | 合成 |
| --- | --- | --- |
| SOLO | 无委派能力，或任务很小 | 一个执行者依序执行、验证、汇报 |
| DELEGATE | 有一个合适的独立专家 | 主 Agent 定契约并验收结果 |
| PARALLEL | 多个节点独立且可安全隔离 | 汇总前逐项核对，最后集成验证 |
| REVIEW | 高风险且有独立审核者 | 实现/审查分离，按证据裁决 |

选定模式后按 `orchestration.md` 执行。
