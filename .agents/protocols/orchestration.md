# 自适应编排协议

## 北极星

每轮工作只有一个**北极星**：明确结果、验收标准、范围、风险与资源约束。所有节点共享它。

## 价值门槛

只有**专项能力、可并行度、独立验证价值**带来的收益，大于上下文传输、整合冲突与管理成本时，才拆蜂群。禁止「能拆五个就拆五个」的数量指标。

## 任务分解（L2/L3）

1. 按依赖划分节点，不按头衔；每个节点产生可独立验收的结果。
2. 标注前置依赖、读写所有权、输入证据、输出与验证方式。
3. 可并行节点的写入范围必须不重叠，或指定唯一写入负责人。
4. 「创建代理配置」不算完成；只有执行结果与证据算完成。
5. 控制上下文：只给相关资料、任务契约、接口约定与禁止项。

角色是**任务期职责**，不是每次都要创建的永久 Agent：

- 研究者：只读文档与事实，不改产品代码。
- 实现者：只改指定模块，不改权限配置与范围外文件。
- 审核者：只读 diff 与验证结果，不直接扩改未授权文件。
- 集成者：核对接口与冲突，只做修复必要的变更。

## 状态机

`PENDING → READY → RUNNING → REVIEW → VERIFIED → INTEGRATED`

- 依赖/权限/材料阻断 → `BLOCKED`，记录事实、需要谁行动、能否降级。
- 验收失败 → `REWORK`，缩小失败范围，修正后重跑检查；不得直接标 `VERIFIED`。
- 取消 → `CANCELLED`，保留恢复信息。
- 只有 `VERIFIED` 节点可进入集成；只有集成检查完成才算最终完成。

## Boids 三原则（工程化）

- **分离**：职责互斥、写入所有权明确、最小权限，避免同文件碰撞。
- **对齐**：所有节点共享同一北极星与验收标准；每个角色只回答自己负责的问题。
- **凝聚**：Map/Reduce 不按人数投票；聚合时检查证据、矛盾、重复实现、接口兼容与验证状态。

## 交叉审核

- L0/L1：定向测试/自查为主，不强制多 Agent。
- L2：关键架构或不确定结论可引入独立审核；有明确增益才用。
- L3：优先互补视角（正确性、安全性）；没有独立代理就说清限制，并执行更严格的本地验证。
- 意见冲突：保留双方证据，按可复现性、事实与既定验收标准裁决。

## 死锁与恢复

- 失败一次：拿到具体错误、复现条件与当前状态。
- 重复失败：缩小原子任务或指定单一救援任务；不无限裂变、不反复重试。
- 合并冲突：保护工作区现状，定点解决；无权限不做破坏性 Git 恢复。
- 需要审批：暂停相应操作，不交给另一个代理规避。

## 输出

使用 `task-contract.md` 的契约与交接格式；长任务按项目既有约定落盘，不为日志额外建目录。
