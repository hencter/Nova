# 证据驱动的记忆与规则演化

## 目标

沉淀可复用教训，而不是自动积累大量日志或让 Agent 悄悄自我改写。

## 三种信息，不混为一谈

| 类别 | 内容 | 默认处理 |
| --- | --- | --- |
| 运行痕迹 | 本次任务的计划、执行过程、失败记录 | 复杂任务才保留；视情况排除版本控制 |
| 可复用经验 | 已验证的错误模式、避坑措施、适用边界 | 有明确后续价值时再整理 |
| 治理规范 | 所有 Agent 的行为要求、批准门槛与协议 | 经过明确评审/授权后才修改 |

项目已存在日志或研究目录时，**优先沿用原路径与约定**，不强制整体搬迁到 `.agents/`。没有现成日志基础设施时，可直接在交付总结中记录，无需建目录。

## 记忆写入门槛

满足下列条件中的大部分才值得归档：

- 有可信的复现或验证证据；
- 经验可跨多个任务复用；
- 给出了明确适用范围及失效条件；
- 不包含密钥、凭证、敏感用户数据或不必要的对话全文；
- 不与当前工程规范/项目约束矛盾。

格式宜短：`问题 → 触发条件 → 验证证据 → 可靠做法 → 不适用范围`。可用 Markdown 双向链接构建索引，但不用为形式增加噪声。

## 自进化是治理变更，不是后台动作

1. 若重复出现某种失败，先验证是规则问题还是执行误差。
2. 提出具体规则差异（现状 → 建议 → 预期收益 → 潜在副作用）。
3. 只在具有实际编辑权限和用户授权的情况下更改治理文件。
4. 验证新规则不会强迫简单任务过度拆解，也不会放宽安全约束。
5. 不强制自动创建复盘代理、运行时间戳脚本或执行 Git 提交。

Skill 的改写与治理协议的改写要分别审核；不要因为一次 Agent 表现不好就批量改动所有 Skills。
